# with icons demos

Seventeen realistic, single-file demo pages (invitations and shops) that flip live from a plain site to a fully upgraded one with
the **with icons** library, in all 34 styles. Open `site/demos/index.html` in a browser (double-click works, no build, no server).

```
site/demos/                 PUBLISHED (deployed with the site to withicons.com/demos/)
  index.html                the hub (generated: node demos/_tools/build-hub.mjs; site header/footer, SEO + JSON-LD)
  <slug>.html               one self-contained page per demo (inline CSS + JS, Google Fonts, self-hosted photos; noindex)
  _kit/demo-kit.js          the floating control bar + settings panel every page loads (levels, 34 styles, size, weight, ink, motion, click-to-swap icons)
  _thumbs/<slug>.jpg        hub thumbnails (generated by shot.mjs --thumb)
  _img/<slug>/<id>-<w>.jpg  self-hosted photo copies (generated by localize-photos.mjs)
demos/                      SOURCE ONLY (never served)
  _data/demos.json          the master brief for all demos (the hub, the authors and the QA read it); "motion": true puts a demo in the hub's "Animated demos" section
  _data/photos/<slug>.json  photo catalogue per demo: Pexels / Unsplash ids, photographer credits, alt text, focal points, local copies (photo.local)
  _kit/playground.html      self-test page for the kit (loads ../../site/demos/_kit/demo-kit.js)
  _tools/                   photos.mjs · localize-photos.mjs · icons.mjs · shot.mjs · sweep.mjs · build-hub.mjs · disclose.mjs
  AUTHORING.md              the contract for writing a page
```

## The three levels

| level | what it is |
|---|---|
| Basic | a plain site as most people build it: emoji and text where icons would go |
| Upgraded | every emoji replaced by a with-icons icon in the chosen style |
| Full | Upgraded plus live icons (dates, clocks, counts, weather, ratings, prices), motion and decorative extras |

The bar at the bottom right of every page changes level and style in one click; the panel adds size, stroke weight, ink colour, motion,
and "Pick icons on the page" (click any icon, search all 734, replace it, or give it its own style). Keys: `i` panel, `[` `]` style, `s` random, `l` level.
The address bar tracks the look (`#ico=gothic&lv=2`), so a link shares it.

## How a page uses the library

Pages never import the library themselves: they mark slots and the kit does the rest.

```html
<span data-ico="calendar" data-size="24">📅</span>                                   <!-- emoji = the Basic fallback -->
<span data-live="calendar-date" data-p-day="31" data-p-month="OCT" data-size="72">31</span>
<script src="_kit/demo-kit.js" data-style="gothic" data-recommend="gothic,halloween,sketch" defer></script>
```

The kit loads `@withicons/web` (and `@withicons/dynamic`, `@withicons/motion`, `@withicons/search` only when used) from jsDelivr, pinned to 0.4.0.

## Tools

```bash
node demos/_tools/icons.mjs search "balloon"            # find an icon; also: check, cats, cat <category>, live, audit <page>
node demos/_tools/photos.mjs build <slug>               # probe every photo of a catalogue; sheet <slug> makes a contact sheet PNG
node demos/_tools/localize-photos.mjs [slug]             # download every photo a page uses into site/demos/_img/ and point the page at it; --check
node demos/_tools/shot.mjs site/demos/<slug>.html --level 2  # screenshots (sliced) + a QA report; --mobile, --click, --eval, --thumb
node demos/_tools/build-hub.mjs                         # regenerate site/demos/index.html
```

## Photos and licences

Photos come from Pexels and Unsplash (both licences allow free use, including self-hosting, without permission; credit is given anyway) and are credited,
photo by photo, with links to the photographer and the photo page, in a "Photo credits" section at the bottom of every page. They are self-hosted:
author a page with the normal hot-link URLs (see AUTHORING.md), then run `node demos/_tools/localize-photos.mjs <slug>`. It fetches each image at the
width the page asks for (capped at 1600 px; Pexels `auto=compress`, Unsplash `fm=jpg&q=75`) into `site/demos/_img/<slug>/<id>-<w>.jpg`, rewrites
src / srcset / CSS `url()` / JS strings to that path, records the paths in the catalogue (`photo.local`) and deletes copies the page no longer uses.
It is idempotent. A page that builds image URLs at runtime (`helper(id, w)`) points its helper at `_img/<slug>/` and lists its widths in the
catalogue as `"localize": { "widths": [...] }`. `--check` fails if any page still hot-links a photo or misses a file. Everything shown (people, places, shops, products) is fictional.

## Deploying

The published pages live in `site/demos/` and deploy with the rest of the site (`scripts/deploy.mjs` uploads everything under `site/`).
The hub is a normal site page (indexed, in sitemap.xml and llms.txt). Each demo page carries `<meta name="robots" content="noindex, follow">`,
a "(demo)" title and a visible "This is a demo" note (`node demos/_tools/disclose.mjs` re-applies all three, idempotently), and is left out of
the sitemap and llms.txt. Do not block them in robots.txt: crawlers must fetch them to see the noindex.

Content-Security-Policy: the demo kit loads `@withicons/web`, `@withicons/dynamic`, `@withicons/motion` and `@withicons/search` from jsDelivr, so
the default `ContentSecurityPolicy` in `infra/site.yaml` allows `https://cdn.jsdelivr.net` in `script-src` (the runtimes and the chunks they import),
`style-src` (motion.css) and `connect-src` (the search index). Google Fonts was already allowed, and photos are self-hosted, so no image host is needed.
The new policy goes live only with a CloudFormation stack update of `infra/site.yaml` (the parameter default changes; if the stack was deployed with an
explicit `ContentSecurityPolicy` value, e.g. from `node scripts/deploy.mjs --print-csp`, pass the new value). Until then the pages fall back to their
Basic level (emoji) on withicons.com. The hub needs no third-party origin.
